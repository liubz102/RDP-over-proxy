## M1 完成情况

全部是纯逻辑，不调用系统接口（`probe.Check` 和 `testutil` 只用标准库网络）。

- **`model`**
  - `Proxy`、`Profile`、`Target`、`Display`，以及 `Normalize` / `Validate`。
  - 校验返回 `FieldErrors`：一次列出全部问题，每条是「字段路径 + 代码」，界面据此逐项标红并翻译。
  - `ParseTarget` 解析 `host`、`host:port`、`[IPv6]:port`、裸 IPv6，`.rdp` 导入和粘贴地址共用。
  - `NewID` 生成 16 位小写十六进制 ID，兼作文件名。
  - 内置「直连」代理，ID 固定为 `direct`，不落盘。
- **`loopback`**：由 ID 经 SHA-256 派生 `127.(1-254).(1-254).(1-254)`；冲突时顺延到下一个空闲地址，搜索覆盖全范围一次，必然终止。
- **`rdpfile`**
  - 只读解析 .rdp，支持 UTF-16（LE/BE）和 UTF-8，有无 BOM 都行；非法字节替换成 U+FFFD，不会整份失败。
  - 能取出目标、用户名（含 `domain` 拼接）、显示设置、`/admin`，`Draft` 直接生成导入用的 Profile 草稿。
  - `Gateway().Verdict()` 判断 RD 网关：不会走 / 可能走 / 一定走。组策略的判断留给 M4。
- **`mstsc`**：`Args` 纯函数组装 `/v /f /multimon /span /w /h /admin`。
- **`probe`**
  - X.224 Connection Request / Confirm 的编码和解码。覆盖 6 种失败码、各种截断、非 RDP 应答，报错时附上收到的前几个字节。
  - `Check`：经线路发送 CR、读取 CC，可用 context 取消，不设超时。
- **`session`**
  - 纯函数 reducer：一次只跑一个步骤，每个步骤以一个事件结束。
  - 停止请求先记下，等在途步骤结束后统一清理；route check 会被主动取消。
  - 上游状态只在翻转时记日志。
- **`testutil`**：假 RDP 服务端，有 7 种应答方式，确认后回显数据，供 M2 隧道测试使用。

## M2 完成情况

还没有接入界面（M4 接入），所以目前只能靠测试验证。测试从不启动真实的 mstsc。

- **`route`**：`Dialer`、`Provider` 接口和直连实现。其他代理类型在 M3 接入，目前返回 `ErrUnsupported`。
- **`tunnel`**
  - 每个连接各自拨上游，双向拷贝，带字节计数。
  - 收到第一个上游字节时报告「已应答」；拨号失败或应答前被关闭时报告「失败」；mstsc 或隧道自己关闭的连接不报失败。
  - `Close` 会取消在途拨号，并等所有 goroutine 退出。
- **`session` actor**
  - 执行 reducer 给出的 effect，结果作为事件放回邮箱。邮箱是无界队列，投递永不阻塞，所以关闭隧道时不会和隧道的报告互相等待。
  - 先执行 effect 再发布状态，因此对外发布的「已结束」一定已清理完毕。
- **`session.Manager`**
  - 每个 profile 最多一个会话；重复连接时聚焦已有窗口；上一个会话还在结束中时，返回 `ErrEnding`。
  - `Quit` 强制结束全部会话，并等它们清理完再返回。
  - 回调串行、按顺序送达：旧会话的最后一条一定先于新会话的第一条。
  - 「直连到本机回环地址」在 preflight 阶段拒绝。
- **`mstsc` 启动器**（Windows）
  - 只用 `System32\mstsc.exe`。
  - 自己持有进程句柄，防止 PID 被复用：关闭、聚焦、结束都只会作用于自己启动的那个进程；进程退出后这些操作什么也不做。
- **`winx`**：按 PID 找可见、无 owner 的顶层窗口，用于 WM_CLOSE 和聚焦。
- **`testutil` 替身进程**：测试二进制以 helper 身份重新运行自己，扮演 mstsc。
  - 一种是屏幕外 1×1 的工具窗口，不激活、没有任务栏按钮，用来验证 WM_CLOSE 能让它退出。
  - 另一种没有窗口，一直运行到被结束，用来验证 Kill。

## M3 完成情况

同样尚未接入界面（M4 接入）。

- **引入 Xray-core v1.260327.0**
  - 它要求 Go ≥ 1.26，`go get` 因此把 `go.mod` 的 `go` 指令从 1.25.0 改成了 1.26。这是对工具链的最低要求，不是应用版本号。
  - exe 体积约增加 23 MB（正式构建参数，不含前端资源：9.9 MB → 32.8 MB）。按 M0 的 11 MB 估算，接入后约 34 MB；M4 接入后实测。
- **`engine`**
  - 每个进程只有一个 Xray 实例，没有 inbound；默认出站是 blackhole，没有带 tag 的连接一律丢弃。
  - outbound 按「代理 ID + 配置摘要」做引用计数：同一代理的多个会话共用一个；修改代理后，新会话用新的 outbound，旧会话继续用旧的直到结束；最后一个使用者释放时，outbound 被移除并关闭。
  - 每个连接用强制 tag 直接交给对应 outbound，不经过 Xray 的路由。
  - 每个连接都挂一个错误 tracker：出站失败时，Xray 给出的原因经由 `Read` 带回给隧道和线路检查。实测能拿到「SOCKS 账号被拒」「HTTP 407」「代理端口拒绝连接」这样的具体原因。
  - 拨号前先校验地址，因为非法地址会让 Xray panic。
  - `connIdle` 调到最大，属于已登记例外。
  - 日志桥接：错误和警告总是转发；info / debug 只在详细模式下转发；每条连接的访问日志不转发，因为里面有目标地址。
  - 直连不经过 Xray。
  - V2Ray 系协议虽然已经被链接进来，但在 M6 写好测试之前一律拒绝（`ErrUnsupported`）。
- **`probe.Latency`**：经线路发一次 HTTP GET，从连接一直算到响应头；任何 HTTP 状态都算通，不跟随重定向，可取消，不设超时。
- **`testutil/xraytest`**
  - 在测试进程里跑真实的 Xray SOCKS / HTTP 代理，可带账号。
  - 单独成包，这样只有需要 Xray 的测试才会链接它。
  - 端口用 `FreePort` 获取（已登记例外），因为 Xray inbound 没法监听 port 0 后再报告实际端口。
- **端到端测试**
  - 隧道 → 引擎 → SOCKS → 假 RDP：数据双向回显。
  - 完整会话（Manager + 引擎 + SOCKS 认证）：先做线路检查，会话结束后 outbound 被释放。
- **`route.DirectOnly` 已删除**：它是 M2 时的过渡实现，现在 engine 统一处理包括直连在内的所有类型。

## M4 完成情况

服务已经接入 app，界面还是 M0 的样子（M5 才做连接、代理页面）。用浏览器预览直接调用服务验证过，见「验证记录」。

- **`errcode`（新包）**
  - 各包的哨兵错误都带上稳定代码，如 `probe.notRdp`、`proxy.auth`、`session.loopbackDirect`。
  - 一棵错误树里取最有用的代码：强代码 > 系统错误（Winsock 错误码，如 `net.refused`）> 弱代码（`probe.noAnswer` 这类通用包装）> `unknown`。
  - Xray 的失败原因只存在于消息文本里（它的重试会把原始错误格式化成文字），所以由 engine 按文本归类：`proxy.auth`（SOCKS 账号被拒、HTTP 407）、`proxy.unreachable`（连不上代理）、`proxy.targetFailed`（代理明确回复连不上目标）、`proxy.dropped`（代理先应答再断开，v2rayN 这类 Xray 服务端到不了目标时就是这样）。都有真实代理的测试。
  - 会话状态和日志行带上 `code`，界面按代码翻译。
- **`secret`（新包）**
  - DPAPI（当前用户）加密代理的 `secret` 和 `outbound`，文件里存 `dpapi:<base64>`。
  - 凭据管理器：只写 GENERIC 类型，目标名 `TERMSRV/<回环地址>`，不带端口（依据见决策记录）。记住的密码用「本机」持久化；一次性密码用「本次登录」持久化，会话结束时删除，崩溃了也会在注销时消失。
  - 能读到并删除 mstsc 自己「记住我」存的域类型凭据，但从不写它。
- **`store`**
  - `proxies\<id>.json`、`profiles\<id>.json`：文件名就是 ID；先填默认值再解码；格式号更新的文件原样保留并跳过；损坏的改名为 `.corrupt`；打不开的（被占用、没权限）原样跳过；解不开的密码（来自别的用户或电脑）清空后照常载入。载入从不整体失败，每个问题都变成一条通知。
  - 新建连接时分配回环地址，全体连接查重；载入时发现地址缺失或冲突，ID 小的保留，其余重新分配并立即保存。
  - 拒绝存 ID `direct`、拒绝把代理设成 direct 类型；被连接使用的代理不能删（返回使用者名单），绝不悄悄改成直连。
- **`mstsc`（续）**
  - `Servers`：写 `UsernameHint`；删除某地址的全部记忆（含证书信任），连同「地址:任意端口」的键，所以改过本地端口后留下的旧键也会清掉。mstsc 用不用端口作键名没查到定论，先两种都写，M5 实测后收敛。
  - `CheckGateway`：读「文档」里的 `Default.rdp`（按已知文件夹定位）和 HKCU 的 RD 网关组策略。`gatewayusagemethod=1`（总是走网关）拦截；可能走网关（值 2、3，或策略启用且强制、或文件交给管理员默认值）只在会话日志里警告。
- **`logging`（新包）**
  - 日志文件 `%LOCALAPPDATA%\RDP-over-proxy\logs\app.log`，每个最多 2 MiB，另留 2 个旧文件。
  - 写入文件前脱敏：用户目录换成 `%USERPROFILE%`（路径里有 Windows 账户名）；已知的目标主机、代理服务器、RD 网关、用户名、连接名、分组名、代理名、代理密码换成 `<redacted>`；非回环 IP 换成 `<ip>`。已知名字只增不减，因为运行中的会话可能还在用已经改掉的主机名。内存里的环形缓冲不脱敏，供界面显示。
  - 连续相同的行只写一次，换了内容时补一句「上一行又重复了 N 次」（按状态翻转去重）。
  - Wails 运行时只收它的警告和错误：它的 debug、info 记录在任何日志级别下都不收，其中有的带着服务调用的参数，也就是密码（代码审查发现）；服务方法返回的预期错误也不收，它们会通过调用结果送到界面；其余记录里的 `args`、`result` 等载荷属性一律写成 `<omitted>`。
- **服务与事件（`api`）**
  - `ProfileService`：列表（含密码状态）、新建、修改、删除、忘记密码。改目标地址删除已存密码；取消「记住密码」只删本程序存的；改用户名时把本程序存的密码挪到新用户名下；删除连接一并清掉密码和 mstsc 对该地址的记忆；连接中的不能删（和「连接」互斥，不会删掉一个正在启动的连接）。
  - 所有凭据操作都经过一把锁，「先查再改」的组合操作在锁内完成；一次性密码不会覆盖本程序记住的密码（会话期间用户改为记住并存了新密码时，以新密码为准）。
  - `ProxyService`：列表（不含密码和 Xray 出站 JSON，两者都含凭据）、读取（含出站 JSON，供编辑）、新建、修改（可保留原密码）、删除、测速（`Latency`，可从前端取消）。
  - `SessionService`：连接（可带密码：「记住密码」的连接把它存为记住的密码，否则只用于本次会话）、断开（可强制）、聚焦、状态列表、会话日志、单独的线路检查（`CheckRoute`，可取消）。
  - `AppService`：通知列表与关闭、应用日志。
  - 事件：`data:changed`（全部连接和代理）、`sessions:changed`、`session:log`、`app:notice`。会话结束时也会发 `data:changed`，因为 mstsc 可能刚记住了密码。
  - 服务返回的错误统一成 `{code, message, fields, args}`，前端在被拒绝的调用的 `cause` 里拿到。
- **接入 app**
  - 启动顺序：先只读地看一眼设置（界面语言、日志级别），再创建 Wails 应用完成单实例判断（第二个实例在这里就退出），然后才正式载入设置（损坏时改名）、打开日志文件、载入数据、启动引擎、清理上次崩溃留下的一次性密码、注册服务。
  - 退出顺序：结束全部会话 → 关闭引擎 → 关闭日志。
  - 有会话在运行时，关闭窗口一律缩到托盘。
  - 设置里改日志级别立即生效，Xray 的 info/debug 只在 debug 级别转发。
  - 设置了 `RDP_OVER_PROXY_HOME` 时，单实例 ID 也按数据目录区分，开发和自测的运行不会与用户正在用的实例互相干扰。
- **前端**：重新生成绑定；`backend.ts` 导出全部服务、类型、事件名和 `errorOf`；两份语言文件加上 `errors`、`notices`、`log` 三组文案。Go 侧有测试检查每个错误码、通知代码和会话日志键在两份语言文件里都有翻译。
- **开发配置**：新增 `.claude/launch.json` 的 `preview` 配置，用 `data\preview` 作数据目录启动浏览器预览。

## M5 完成情况

界面已经能完成全部日常操作，2026-10-03 用户在真实环境里逐项验收通过（见「验证记录」和「实连反馈与修复」）。

- **连接页**
  - 按分组列出连接（有分组时才显示分组标题），每行显示地址、代理、用户名和会话状态；状态点分灰、蓝、绿、黄、红五种。
  - 按钮跟着状态变：连接 → 取消（启动中）→ 切换到窗口 + 断开（运行中）→ 强制结束（断开中）。「更多」菜单：编辑、检查线路、查看会话日志、忘记已保存的密码、强制结束、删除。连接中不能删除、不能单独检查线路。
  - 状态文字：「已连接」要等远程计算机经线路应答过才显示，之前是「远程桌面已打开」；线路断了显示黄色的「连不上远程计算机」和原因；失败的会话显示失败的步骤和原因。点状态文字打开会话日志。
  - **编辑框**：名称、分组（可选已有分组，也可新输入）、计算机（一个框，可写 `host`、`host:port`、`[IPv6]:port`）、代理、用户名、记住密码与密码、显示（默认 / 全屏的三种显示器用法 / 窗口宽高）、`/admin`。Go 侧返回的字段错误逐个标在对应输入框下。改了计算机并且有已保存的密码时，提前提示保存后会删除密码。
  - **连接前的密码框**：只在「有用户名、并且本程序和 mstsc 都没存密码」时弹出。可以改「记住密码」（先存进连接设置再连接），也可以不填，让远程桌面自己问。
  - **检查线路**：对话框里转圈，关掉即取消；成功显示用时和安全协议，失败显示原因和原文。
  - **会话日志**：右侧抽屉，上方是当前会话的入口地址、进程、连接数、线路检查结果，下面按时间列出翻译后的日志；错误行附原文。打开时先读一次，之后靠事件追加。Go 侧给每条会话日志编了递增序号（`Line.Seq`），读到的和推来的按序号合并，谁先到都不会重复或遗漏。
- **代理页**：「直连」固定在第一行；每行显示类型、地址、账号、被几个连接使用；测速可取消，结果显示毫秒数或原因。编辑框只有 SOCKS5 / HTTP（V2Ray 系在 M6），服务器框可直接粘贴 `地址:端口`；编辑时密码框留空即保留原密码，也可以明确清除。删除被使用的代理时，确认框里列出在用的连接名。
- **通知**：启动时读取已有通知，之后靠 `app:notice` 追加，显示在页面顶部，可逐条关闭。
- **退出**（「待用户回答的问题」里的建议方案）：侧栏底部加了「退出」。没有会话时直接退出；有会话时弹确认框，说明会断开几个远程桌面。托盘的「退出」在有会话时先把窗口调出来，再弹同一个确认框；确认框还没回答时再点一次托盘「退出」就直接退出，以防页面坏了弹不出框。Go 侧新增 `AppService.Quit(confirmed)`、`AppService.KeepRunning()`（取消）和 `app:quitRequested` 事件。
- **启动读取与事件的先后**：启动时读取列表、会话、通知的同时，Go 侧可能已经推来更新。读取回来时，期间被事件改过的内容（数据、某个会话）以事件为准，通知取两者的并集。
- **设置保存排队**：设置每次保存整份对象，所以保存一个接一个执行，每次都基于上一次存好的结果。
- **设置页**：新增「连接」（本机入口端口、启动前先检查线路）和「高级」（测速网址、日志级别）。文本框在失焦或回车时才保存，不合法时不保存并提示。
- **错误显示**：标题是 `errors.<code>` 的翻译；只有网络、代理、探测、凭据这类原因才附上英文原文，「代理正在被使用」之类翻译已经说清楚的不再重复。出错的操作用右下角的提示条，停留到手动关闭。
- **前端测试**：新增 6 个测试文件，覆盖地址拆分、连接 / 代理表单转换、会话状态到界面的映射、日志合并、错误 / 日志 / 通知的翻译，以及按代码拼出来的文案键在两份语言文件里都存在。

## M6 完成情况

V2Ray 系协议全部可用：VMess、VLESS（含 REALITY、Vision、VLESS Encryption）、Trojan、Shadowsocks（含 2022）、Hysteria2，以及自定义 Xray 出站。每种都用测试进程里的真实 Xray 服务端连通过（见验证记录），还没有经用户的真实节点验证。

- **数据结构（model）**
  - 代理新增 `options`（`ProxyOptions`）：协议自己的选项、传输方式、安全层，字段名照分享链接的参数取。`Normalize` 只留下这种代理、这种传输和安全层用得上的项，并补上默认值，存下来的就是实际用的。
  - `secret` 统一表示登录凭据：密码，或 VMess / VLESS 的用户 ID。`outbound` 只给自定义出站用。
  - 校验逐个字段给出问题：用户 ID 的格式（UUID，或 1–30 字节的自定义 ID）、SS2022 密钥的长度、REALITY 公钥 / Short ID / SpiderX、证书指纹、ALPN、路径、JSON 字段。冲突：REALITY 只能配 TCP、XHTTP、gRPC；Vision 流控要 TCP 加 TLS / REALITY，或者 VLESS Encryption；mKCP 的伪装和种子不能和 finalmask 同时用。
  - 列表显示用的 `Transport()`：传输方式和安全层；自定义出站从它的 `streamSettings` 里读。
- **存储**：`options` 和 `secret`、`outbound` 一样用 DPAPI 加密后存盘（文件里是一段 `dpapi:` 密文）。解不开时照常载入并给出通知。文件格式号不变，新字段是增加的。
- **分享链接（新包 `sharelink`）**
  - 能读：vless、trojan 和标准格式的 vmess（XTLS discussion #716）；v2rayN 的 vmess（base64 的 JSON，成员是字符串或数字都认，还认第一版的 `host;路径`）；ss（SIP002，用户信息是 base64 或 2022 方法的明文；旧式整段 base64）；hysteria2 / hy2；socks / socks5 / http（账号明文或 base64）。
  - 直接拒绝：无效链接、不认识的协议、h2 / quic 传输（Xray 已经删掉）、旧 XTLS、SS 插件、不认识的 Hysteria2 混淆。
  - 只提示、照常导入：要求跳过证书验证（Xray 已不支持，照常验证）、VMess 的 alterId 不是 0、没用上的参数、端口跳跃（只用第一个端口）。
  - 能写：vmess 用 v2rayN 的格式（放不下的设置改用标准格式），其余用各自的格式。读出来的每种代理写回链接再读一遍，结果完全相同（有测试）。
- **引擎（engine）**
  - 生成各类代理的 Xray 出站：VMess / VLESS / Trojan / SS 用 Xray 的扁平写法加 `streamSettings`；TCP 的 HTTP 伪装；mKCP 的伪装和种子转成 `finalmask`（Xray 26 把它们挪了过去）；Hysteria2 的 h3 ALPN、Salamander 混淆、QUIC 保活；REALITY；自定义出站去掉 tag 后原样交给 Xray。
  - `Check`：保存前用 Xray 的配置代码检查一遍，不加进实例。Xray 碰到某些畸形值会直接 panic（比如截断的 VLESS Encryption），model 校验先挡住已知的，构建时 recover 兜底。
  - 失败原因新增 `proxy.tls`（证书不是指定的那张、REALITY 公钥不对）；Hysteria2 密码错归入 `proxy.auth`。VMess、VLESS、Trojan 的服务器对认不出的客户端什么都不说，只能看到连接被关，`probe.noAnswer` 的文案里提到了这种可能。
  - Xray 每次构建 VMess、Trojan、gRPC 等出站都会警告「已弃用」，日志桥接把它降为 info。
- **服务（api）**
  - 新增 `ProxyService.ParseLink`、`ShareLink`、`DraftLatency`（测还没保存的设置）。
  - `Create`、`Update`、`DraftLatency` 先做字段校验，再让 Xray 检查（`Deps.CheckProxy`，即 `engine.Check`）；Xray 不接受时返回 `proxy.config`，附 Xray 的原文。
  - 「保留已存的密码」只在类型不变时生效，VMess 的用户 ID 不会被当成 Trojan 的密码。
  - 列表里不带 `options`、`outbound`、`secret`，只带传输摘要。日志脱敏加上用户 ID、SNI、Host、路径、serviceName、公钥、Short ID、种子、混淆密码，以及自定义出站里的地址、ID、密码、serverName 等。
- **界面**
  - 代理编辑框：顶部粘贴分享链接，读取后填好表单并列出提示；类型下拉框有全部 8 种；按类型显示账号 / 密码或用户 ID、协议选项；VMess、VLESS、Trojan 另有「传输」「安全」两节；少用的设置收在「高级设置」里，链接带了这些值时自动展开；自定义出站是 JSON 文本框；底部「测速」测当前还没保存的设置。
  - 列表每行显示传输摘要（如「WebSocket + TLS」）；「更多」菜单加了「复制分享链接」。
  - 代理页空状态的文案改为说明分享链接。
  - 编辑已保存的代理时，对话框等数据读完才打开（见下面的「预览发现的问题」）。
- **测试**
  - Go：model（选项的默认值和清理、各项校验）；store（选项加密存盘、解不开时照常载入）；sharelink（24 种写法的解析、14 种拒绝、17 种往返、生成格式）；engine（20 种组合经真实 Xray 服务端完成 RDP 握手、两种测速、6 种失败原因、自定义出站、Xray 拒绝的配置、mKCP 和 Hysteria2 的生成）；api（链接、保存前检查、保留密码、草稿测速、日志脱敏）。
  - `xraytest` 能按客户端设置起对应的服务端：各协议、各传输、自签名证书（客户端用证书指纹信任它）、REALITY 的密钥和目标站点。
  - 前端：代理表单（换类型、按链接填表、保留密码、字段映射、分区）、按代码拼出的文案键。

**代码审查后的修改**（独立子代理审查，11 条全部修复）
- **链接里精心构造的 finalmask 能让程序崩掉**：比如 fragment 长度写成负数，Xray 照收不误，连接时在它自己的 goroutine 里切片越界，recover 不到。改为：这些 JSON（`finalMask`、XHTTP 的 `extra`、自定义出站的掩码和 XHTTP 设置）里不许出现负数；链接和表单里的 finalmask 只认服务器需要的几种（伪装头、mKCP 混淆、Salamander）；engine 生成出站前一律先做完整校验，哪里来的代理（包括手改的文件）都到不了 Xray。
- **解不开的设置会退回默认值**：从别的电脑拷来的代理，设置变成「无 TLS」，用户只补填用户 ID 就保存的话，用户 ID 会不经加密发出去。改为：解不开的代理标记为「需要重新填写」，重新保存之前拒绝用它连接和测速，编辑框里明确说明下面是默认值；Trojan 默认 TLS；通知文案改为建议重新粘贴分享链接。
- **v2rayN 格式的 VMess 链接后面多了 `#名称`**：v2rayN 把 `vmess://` 后面整段当 base64 解，会解不开。名称本来就在 JSON 里，不再追加。
- **编辑框的「清除密码」状态**：从不带密码的链接新建代理后，密码框被禁用且没法恢复；换类型后已输入的密码被丢弃。改为只在编辑已存密码、且类型相同时才清除，输入新密码或换类型都会解除。
- **SOCKS5 和 HTTP 互换时丢了已存的密码**：两者的账号是一回事，改为保留。
- **保存前的检查没覆盖建出站时才报的错**：`Check` 改为在实例里实际建一次出站再删掉（不会连网）；VLESS Encryption 的 padding 按 Xray 的规则校验；Salamander 密码至少 4 个字符。
- **Vision 配 TCP 的 HTTP 伪装能通过校验，运行时才失败**：改为冲突。
- **在 gRPC 和 XHTTP 之间换传输方式，旧的模式留着导致保存失败**：换传输方式时模式和伪装类型回到默认。
- **链接往返丢东西**：Hysteria2 的 `vcn`；v2rayN JSON 里写成 `mkcp` 时种子丢了；SIP022 链接里编码过的 `:`。都已修正并加了测试。
- **日志脱敏**：漏了掩码和 XHTTP extra 里的密码、自定义出站里的 secretKey、preSharedKey 和请求头；又把「grpc」「/ws」这类常见词到处换成 `<redacted>`。改为收集这些值，同时跳过常见词和本机回环地址。
- **测速还在进行时改了设置，结果会算到新设置头上**：改设置时取消进行中的测速。
- **mKCP 不带伪装、种子和 fm 时默认加 `mkcp-original`**：这是 Xray 26 之前所有 mKCP 服务端都用的混淆；新版服务端不配混淆时是裸 mKCP，要在 Finalmask 里填 `{"udp":[]}`，提示里写明了。
- 另外，审查后的预览里发现并修复：测速失败的长文字把代理列表的一行撑坏（`Caption1` 是行内元素，`maxWidth` 不生效）；日志桥接调整后，Xray 的启动行（带版本号）在默认级别下不再写入日志。

**预览发现的问题**
- **编辑代理时焦点被抢走（M5 起就有）**：编辑框先转圈、读完代理再出表单。对话框打开时里面没有可聚焦的东西，Fluent 的焦点陷阱（tabster modalizer）没有激活，之后每次在对话框里获得焦点，都会在 100 毫秒后被拉到对话框外（「更多」按钮）：下拉框一开就关，输入框只能打进一个字。改为读完数据再打开对话框。新建代理、新建 / 编辑连接打开时都有输入框获得焦点，不受影响。
- 提示条和「高级设置」链接在可滚动的内容区里被压扁、和下面的标签重叠：子元素加 `flexShrink: 0`。
- 「读取」按钮和输入框没对齐：改放在输入框里。
- REALITY 链接带 `allowInsecure` 时也提示「证书指纹」：改为只在 TLS 时提示；`spx=/` 是默认值，不再让「高级设置」自动展开。
- 技术字段（链接、地址、用户 ID、JSON 等）关掉拼写检查；换类型时清掉上一种类型的错误提示。

**代码审查后的修改**（独立子代理审查，9 条全部处理）
- **读不出 Default.rdp 时，错误文字带着它的完整路径**，进了会话日志、日志文件和「复制诊断信息」。「文档」被重定向时，路径里会有公司的 OneDrive 名或文件服务器名和账户名（日志的脱敏只换得掉本机用户目录）。改为：`ReadDefaults` 只报原因、不带路径；诊断报告再保险一次，路径只放在不复制的细节里。
- **漏了机器组策略「为客户端配置服务器身份验证」**：它启用时决定一切，Default.rdp 里的设置不起作用（本机 TerminalServer.admx 核实：`HKLM\…\Terminal Services` 的 `AuthenticationLevel`）。改为读它并优先；诊断页和会话日志说明是组策略、只能由管理员改。另外没有 Default.rdp 时按 mstsc 自己的默认值「显示警告」，不再显示「未指定」。
- **WMI 卡住会让诊断页一直转圈**（WMI 仓库损坏时正是会来看诊断的时候）。规则不允许设超时，改为：报告不等 Credential Guard，第一次打开时在后台只查一次，这一行先显示「正在检查…」，查完经 `diag:changed` 事件带着新报告刷新；结果保留到程序退出（Credential Guard 要重启才会变）。
- **中文措辞和中文 Windows 的界面对不上**（本机 mstsc.exe.mui、CredSsp.adml 核实）：「始终要求凭据」（原写「总是」）；服务器身份验证的选项是「连接并且不显示警告 / 不连接 / 显示警告」，标签「如果服务器身份验证失败」；组策略叫「加密数据库修正」，选项「强制更新的客户端 / 已缓解 / 易受攻击」。同时改正了含义：「已缓解」同样不会连接没打 CredSSP 补丁的远程计算机，和「强制更新的客户端」的区别在本机作为服务器时。
- **不知道是否加入域时，「经隧道使用保存的密码」却判成「允许」**：改为「无法确定」。
- **检查线路的结论只看步骤成败**：代理已不存在、密码解不开、直连到本机这类设置问题，也被说成「多半是代理的问题」或「检查防火墙」。改为这些情况结论是「这个连接的设置有问题」。
- **导入还在读文件时点了「新建连接」，会开出标题是导入、表单却是空的对话框**：已经开着对话框时，导入的结果不再顶替它。
- 小问题：没有 Default.rdp 时打开的 mstsc 选项是收起的，提示里加上「先点显示选项」；打开日志文件夹的 ShellExecute 按微软要求先初始化 COM（和 WMI 共用一个 `withCOM`）。
- 审查提到的文档未更新（CLAUDE.md、PROGRESS）是审查开始时还没写，现已更新。

**预览发现的问题**
- Credential Guard 原来按 `LsaIso.exe` 进程判断，在用户的 Win10 专业版上显示「正在运行」；`Win32_DeviceGuard` 说没有运行（Key Guard 也会启动 LsaIso，专业版不能开 Credential Guard）。改为查 WMI；它返回的是变体数组，判断改为接受任何整数类型。
- 「标签：允许：……」这类双冒号读着别扭，改成句号。

**本机代理检测**（计划里的「空状态和本地代理检测」，2026-10-06）
- 还没有自己的代理时，连接页（还没有连接时）和代理页的空状态下面多一张卡片「这台电脑上正在运行的代理」，列出检测到的代理，每个一个「添加」。什么都没找到就不显示。
- 怎么找（新包 `internal/localproxy`，只读）：
  - 读本机在监听的 TCP 端口和所属进程（`winx.Listeners`，`GetExtendedTcpTable`）、进程列表（文件名和父进程，`winx.Processes`）、系统代理设置（`winx.SystemProxy`，HKCU 的 Internet Settings）。
  - 只看已知代理软件的端口：文件名是已知的软件（v2rayN、Clash Verge、Clash for Windows、NekoRay / NekoBox、Hiddify、Shadowsocks 等），或者以已知内核开头（xray、v2ray、wv2ray、sing-box、mihomo、clash、hysteria 等）。端口按监听进程往上找到的第一个已知软件命名，找不到就用文件名：v2rayN 3 的内核叫 wv2ray.exe，名称显示 v2rayN。
  - 监听 0.0.0.0 的用 127.0.0.1 去连；监听 `::` 的先试 127.0.0.1 再试 ::1，因为套接字表看不出它收不收 IPv4（你机器上的 v2rayN 就是 `[::]:10808`）。
  - 一个软件往往有好几个端口（HTTP 代理、控制 API），所以逐个发 SOCKS5 问候（提供「无认证」和「用户名密码」两种方式），只列出按 SOCKS5 应答的。只发问候、读它选的方式就关，不发连接请求，代理不会去连任何地方（转发端口例外，见下面「代码审查后的修改」）。只探测本机回环地址。
  - 别的协议的端口收到问候后可能一直等下去，所以不设超时（规则）：卡片消失时，界面取消还没回答的探测；新一轮检测和退出也会结束上一轮的。
  - 系统代理指向本机、而且监听它的不是已知软件时，作为 HTTP 代理列出，不探测（WinINet 的 `socks=` 是 SOCKS4，不用）。

- 卡片里的按钮是次要按钮：一个画面只放一个主按钮（「新建连接」或「添加代理」）。代理页的空状态跟在「直连」那一行后面，上边距收小（`EmptyState` 的 `compact`），卡片不用滚动就能看到。

**代码审查后的修改**（独立子代理审查，2026-10-06；没有阻断问题，9 条里改了 8 条）
- **端口表在读的时候变了，Windows 会答 `STATUS_UNSUCCESSFUL`**（psutil 碰到过，giampaolo/psutil#1294），原来整个检测就失败、卡片不出现。改为：重新问一次大小，大小确实变了才重读（依据是 Windows 给的大小，不计次数），没变就报错；IPv4、IPv6 一个读不出来不连累另一个。
- **父进程的 ID 可能已经被重用**：explorer.exe 的父进程 userinit.exe 早就退出了，它的 ID 可能被开机启动的 v2rayN 拿到，之后从资源管理器启动的 sing-box 就会被叫成「本机 v2rayN」。改为：进程列表带上启动时间，只认比子进程先启动的父进程，任一方的启动时间不知道就停。
- **日志抽屉每来一行都重算、重画全部 1000 行**：详细级别下 Xray 一次来一串时会卡。改为：每行要显示的文字只算一次（按语言、连接名和日期失效），已经显示的行不重画，同一帧里来的行合并成一次更新（显示用，窗口看不见时不画，看见时一次画完）。用 300 行一次到达验证：按顺序一次显示，停在最新一行。
- **抽屉关闭时取消读取，会在控制台打一条错误**：和本机代理卡片一样，卡片或抽屉已经不在就不打。
- **探测在浏览器预览里取消不了**：服务端 30 秒后放弃请求，之后界面的取消送不到 Go 侧，不回答的端口（比如 Clash 的控制 API）每打开一次页面就留下一个连接。改为：每次 `LocalProxies`（新一轮检测）和退出都会结束上一轮的探测。桌面版关窗口本来就会取消。
- **「代理不会去连任何地方」不完全对**：转发端口（Xray 的 dokodemo-door、Clash 的 tunnel）会把这 4 个字节转给它的固定目标。改了注释，TROUBLESHOOTING 里也写明了；检测只在还没有自己的代理时进行。
- `Logger.Watch` 的说明改准确：`stop` 返回后记的行一定不会再送出，正在送的那一行可能还会送完（`Core.Quit` 之后最多一次多余的事件，无害）。
- 「关于」里说许可证全文随发布版本提供，现在还没有发布：M9 的 release 工作流要带上 THIRD_PARTY_NOTICES（记在下一步里）。
- 没改的一条：**已知代理软件只开了 HTTP 端口、又被设成系统代理时**（比如 `gost -L http://:8080`），不会列出，见已知问题。v2rayN、Clash 都有 SOCKS5 或混合端口，列得出来。

## 实连反馈与修复

- **2026-10-03 RD 网关误报**：用户的 mstsc 设的是「自动检测 RD 网关服务器设置」，连接却被拦下，提示「总是通过 RD 网关」。原因：Default.rdp 里是 `gatewayprofileusagemethod:i:0`（自动检测，也就是用管理员 / 组策略的设置），旁边的 `gatewayusagemethod:i:1` 只是灰掉的「使用这些设置」里残留的旧值，mstsc 不会用它；判断时却把它当了真。修复：
  - 文件写明自动检测（`gatewayprofileusagemethod` 为 0）时，只看组策略，文件里的 `gatewayusagemethod` 和服务器名一律不算；没有启用的组策略就是不走网关。
  - 文件里没有 `gatewayprofileusagemethod` 这一行（手写的 .rdp）时，不知道 `gatewayusagemethod` 算不算，所以「总是」也只警告、不拦截。
  - 用用户机器上真实的 Default.rdp 和组策略跑了一次（临时测试文件，跑完已删）：结果是「不走网关」。
- **同一次发现：日志里显示了 `{{server}}`**：错误自带的参数（网关服务器名）只放在会话状态里，没有带进会话日志行。修复：错误参数机制挪进 `errcode`（`WithArgs` / `Args`），会话日志行多带一个 `errorArgs`，前端翻译日志时填进去。

- **2026-10-03 询问密码时点「断开」会卡住**：mstsc 正在询问密码时点「断开」，凭据框消失，但 mstsc 进程没有退出，也再没有任何窗口；界面停在「切换到窗口 / 断开」，两个按钮都没反应，也不能重新连接，只有退出本程序时才把它结束（日志里是一串 `the process has no window`）。原因：「断开」给 mstsc 的所有可见窗口发关闭消息，当时可见的只有凭据框（和连接进度框），关掉它们让 mstsc 卡死；而会话按设计要等 mstsc 自己退出。修复：
  - 只给远程会话窗口（类名 `TscShellContainerClass`，就是会弹「远程会话即将断开连接」的那个）发关闭消息，并且只在它可用时发（被 mstsc 自己的对话框挡住时是禁用的）。
  - 没有这样的窗口（还在连接、在询问密码，或开着它自己的对话框）就没人能确认断开，直接结束 mstsc，日志说明原因。远程计算机那边和正常断开一样，已登录的会话会保留。所以在 mstsc 的确认框还开着时再点一次「断开」，也会直接结束。
  - 「切换到窗口」优先调出会话窗口，没有的话调出 mstsc 当时显示的窗口（比如凭据框）。
  - 用替身窗口测试：别的类名的窗口（代表凭据框）、被禁用的会话窗口都不会被关，并报告「没有可以问的窗口」；会话收到后结束 mstsc。
- **2026-10-03 UsernameHint 只写不带端口的键**：见验证记录。你机器上以前写的 `127.x.y.z:13389` 键留着无害，删除对应连接时会一起清掉。
- **2026-10-06 远程桌面窗口标题只有 127 地址**：原型的标题是「连接名（走代理） - 127.x.y.z:13389 - 远程桌面连接」，新版变成了「127.x.y.z:13389 - 远程桌面连接」，看不出连的是哪台电脑。原因：mstsc 标题里的连接名取自 .rdp 文件名，原型每次生成一个以目标命名的临时 .rdp；新版为了避开 2026-04 补丁后打开 .rdp 必弹的安全提示，只用 `mstsc /v:` 启动（2026-10-02 的决定），没有文件名，标题里就只剩地址。修复：
  - mstsc 启动后，本程序把连接名加到远程会话窗口（`TscShellContainerClass`）标题的最前面：「办公室 - 127.x.y.z:13389 - 远程桌面连接」，和 mstsc 用 .rdp 文件打开时显示文件名一样；后半段仍是 mstsc 自己的文字，跟着系统语言。名称不再像原型那样被截在第一个「.」前。
  - 用 WinEvent 钩子盯着这个 mstsc 进程的窗口（显示、标题变化），先装钩子再看已有的窗口，所以窗口出现得再早也不会漏。mstsc 自己改回标题（比如重新连接时）就马上再加上，完全靠事件，不轮询。
  - 改标题是给窗口发 `WM_SETTEXT`，和 mstsc 自己改标题完全一样（标题栏重画、任务栏更新都由它自己处理）。跨进程的 `SetWindowText` 不发这个消息，只改 Windows 存的文字（实验确认，见验证记录）。发消息要等 mstsc 处理完，所以放在每个会话自己的线程上；mstsc 退出时结束，卡住的 mstsc 被结束后它也跟着返回。
  - 处理 `WM_SETTEXT` 时立刻把自己的标题改回去的窗口，试一次后就不再改，否则两边会一直轮流改下去。
  - 加不上名称（比如钩子装不上）不影响连接，会话日志里记一条「操作「showName」失败」的警告。

1. **删除被使用的代理**：原来直接拒绝。改为确认框里警告、列出会改成直连的连接，确认后照删，这些连接改为「直连」。
2. **在列表里选代理**：连接列表每行加代理下拉框，「编辑连接」里去掉「代理」。
3. **连接打开时锁住相关设置**：连接启动后再改设置，当前连接不会跟着变，容易误解。改为连接打开期间（包括正在连接、正在断开），这个连接相关的设置都锁住，断开后才能改。
4. （补充）连接打开时那一行多了「切换到窗口」，和下拉框位置冲突：连接打开时照旧显示「经 xxx」、不显示下拉框；未打开时去掉「经 xxx」、显示下拉框。

**Go 侧**
- `store`
  - `DeleteProxy(id, moveToDirect)`：只把调用方点名的使用者改成直连；名单外还有使用者就什么都不动，返回 `InUseError` 列出那些连接。先改写连接文件，最后删代理文件，中途失败也不会有连接指向不存在的代理。
  - 新增 `SetProfileProxy`。`UpdateProfile` 保留原来的代理：编辑框没有这一项，免得用打开时的旧值把列表里刚选的改回去。
  - 代理只在「选」的时候要求存在（新建、`SetProfileProxy`）。代理文件读不出来时，连接的其他设置照样能改，列表标「代理已不存在」。
- `api`
  - 新增 `ProfileService.SetProxy`；`ProxyService.Delete` 多一个参数 `moveToDirect`，改成直连的连接 ID 记入日志。
  - 连接打开期间：`ProfileService.Update`、`SetProxy`、`ForgetPassword`（和原有的 `Delete`）返回 `session.running`；它用的代理，`ProxyService.Update`、`Delete` 返回新错误码 `proxy.connected`，列出已连接的连接名。
  - 检查和修改在同一把锁（`Core.lifecycle`，`Connect` 也持有它）里完成。`Update` 连同后面的密码清理一起持锁，否则恰好开始的会话的一次性密码可能被当成旧计算机的密码删掉。
  - 界面上的「锁住」是给人看的，依据是 Go 侧的拒绝；两边判断的都是「会话还没结束」。

**界面**
- 连接列表：未连接的行显示代理下拉框，选了立即保存。下拉框宽 160px，长名字显示省略号；展开的列表按名字放宽，最多 320px，向左展开（按钮靠右）。代理不存在时，下拉框里是红字「代理已不存在」。连接中的行显示「经 xxx」。
- 编辑连接：去掉「代理」。连接中打开是只读的：顶部说明「这个连接正在使用中，断开后才能修改设置」，按钮是「关闭」，会话结束后当场解锁。「更多」里的「忘记已保存的密码」连接中禁用。
- 新建连接仍默认用第一个自己的代理（没有就直连），建好后在列表里改。
- 删除代理：确认框用警告色列出会改为直连的连接；有连接正通过它连接时，改为说明「断开后才能删除」并禁用「删除」。内容随数据实时变化，确认时把列出的连接交给 Go 侧。
- 编辑代理：有连接正通过它连接时只读，顶部列出这些连接；「测速」仍可用。

**预览发现的问题**
- 字段全禁用时，Fluent 对话框把焦点给了内容区里剩下的唯一可聚焦元素「显示高级设置」，内容滚到底，顶部的说明看不见。锁住时不显示这个链接：有值的高级设置一打开就是展开的，折叠着的都是空的。
- 确认框的「删除」禁用后仍是红色：`ConfirmDialog` 的红色样式盖住了禁用样式。改为禁用时用普通的禁用样式。
- 下拉列表一开始和按钮一样宽，长名字折成三行；放开宽度后，Fluent 把它挪到了按钮上方（右边放不下），并用内联 `max-width` 盖掉了样式里的上限。改为右对齐、只让 Fluent 限制高度。

**测试**
- Go：store（删除时只改点名的连接、名单外有使用者时不动、重新载入后仍是直连；`SetProfileProxy`；`UpdateProfile` 不改代理；代理不存在时仍能编辑、不能新选）；api（删除的几种情况；`SetProxy`；连接中各项修改被拒，会话结束后都能改）。
- 前端：`isActive`、`proxyUsage`、表单不再带代理。

## 已知问题

- **本机代理检测只认得列出的软件和系统代理**：别的软件开的本地端口要手动添加。没有应答的端口（HTTP 代理、控制 API）的探测会一直等到卡片消失（或下一轮检测、退出）才取消，每个只占一个本机连接。已知代理软件只开了 HTTP 端口、又被设成系统代理时也不会列出（它自己的端口不按 SOCKS5 应答，系统代理又因为是已知软件的端口而跳过）。
- **程序日志里 Wails 运行时自己的行（警告和错误）不实时出现**，打开抽屉时才读到，见决策记录。
- **日志查看器显示原文**（主机名、用户名都在），给自己看；附到 Issue 的是日志文件（已遮盖），TROUBLESHOOTING 里写了。

- **窗口标题加连接名只用替身窗口测过**：自测不能启动真实的 mstsc（会改它的最近连接记录和 Default.rdp）。要用户实连时看：窗口标题、任务栏按钮、Alt+Tab 里是不是「连接名 - 127.x.y.z:端口 - 远程桌面连接」；切换全屏 / 窗口、断线重连之后名称还在不在；全屏时顶部连接栏显示什么（那是 mstsc 自己画的，不一定跟着标题变）。
- **经 UAC 建文件夹的完整流程没有实测**：自测不能替用户点 UAC，也不往 Program Files 放东西。分开验证过的有：说明框会弹出，提权的助手不提权直接运行时能建好文件夹并授权，`Prepare` 遇到拒绝写入的目录时会报出权限错误。点「确定」之后的那一段（UAC、提权运行、再检查一次）要用户实测。
- **数据文件夹放在多人共用的位置时，能读这个文件夹的人都能看到连接和代理设置**：密钥是加密的，主机名、用户名不是。这是「数据跟着程序走」的代价，SECURITY 里写了。
- **`mstsc /edit` 在 Default.rdp 不存在时的行为没有实测**：所以这时改为打开普通的「远程桌面连接」（在「显示选项」里改好后点「保存」也会生成它）。
- **「始终要求凭据」按微软文档对 `prompt for credentials` 的说明理解**，没有对照 mstsc 实测；会话日志里只是提醒。
- **不支持把 .rdp 文件拖进窗口导入，一次也只导入一个**：见决策记录。
- **WMI 一直不回答时，诊断页的 Credential Guard 会一直是「正在检查…」**：不设超时（规则），其余各项照常显示。
- **检查线路的「代理」一步用的是「设置」里的测速网址**：代理服务器那边打不开这个网址时这一步会失败，结论里会说明不影响远程桌面。
- **mstsc 自己的「记住我」在 Win11 上可能无效**：它存的是域类型凭据，Credential Guard 开启时不能委派，每次还会再问密码。本程序存的 GENERIC 凭据不受影响。
- **V2Ray 系协议还没有经过真实节点**：都是和测试进程里的 Xray 服务端互连。和其他实现的服务端（v2ray、sing-box、Hysteria 官方服务端）的兼容性，要靠用户实连。
- **mKCP 和旧版 v2ray 服务端的兼容性是按代码推断的**：Xray 26 把伪装和种子挪进了 finalmask，本程序按旧 mKCP 的包格式排列（伪装头在前，混淆或 AES-GCM 在后），只和 Xray 服务端互连测过。
- **不支持的**：Shadowsocks 插件（obfs-local、v2ray-plugin）、Hysteria2 的端口跳跃（只用第一个端口）和带宽设置、Xray 已删掉的 h2 / quic 传输和 `allowInsecure`；分享链接和表单里的 finalmask 只认伪装头、mKCP 混淆和 Salamander（fragment、noise 等客户端自己加的掩码要用自定义出站）。
- **自定义出站只挡住了负数**：它可以用任何掩码，写个大得离谱的正数尺寸（比如几 GB 的 noise）仍可能让 Xray 吃光内存。这是用户自己写的配置，没有再逐项限制。
- **mKCP 的默认混淆有歧义**：不带伪装、种子和 fm 的 kcp 链接按旧服务端处理（加 `mkcp-original`）；新版 Xray 服务端不配混淆时连不上，要在 Finalmask 里填 `{"udp":[]}`。
- **浏览器预览里复制不到剪贴板**：预览版的剪贴板是空操作；桌面版正常。
- **浏览器预览被直接结束进程时不会走退出流程**（日志里没有 stopped）。这是预览工具的结束方式，桌面版正常退出已验证。
- **前端体积**：bundle 约 900 KB（M5），主要是 Fluent UI，暂不处理。
- **会话状态的界面只在单元测试里验证过**：自测规则不允许点「连接」（会启动 mstsc），所以「已连接」「连不上远程计算机」「失败」这些状态在预览里没有实际出现过，要靠用户实连时看。连接中的锁定（只读的编辑框、删除代理的限制）在预览里用推送假的会话事件看过，只改了前端状态。
- **exe 体积**：35.6 MB（M4 实测），36.1 MB（M6），36.3 MB（M7），36.5 MB（M8 换图标后，exe 资源和托盘各带一份 icon.ico）。`infra/conf` 会把 Xray 几乎所有协议和传输都链接进来，精选 import 也省不了多少。
- **Xray 的日志处理器是进程级全局的**：每创建一个 Xray 实例都会把它替换掉。应用里只有一个实例，没有问题；但测试要检查引擎日志时，必须先启动 `xraytest` 代理，再启动引擎。
- **代理端口不通时，要等 Xray 内部重试约 1.5 秒才会报错**：这是 Xray 自己的行为，不是本程序的超时。
- **标题栏颜色**：只跟随系统主题，不随应用内的主题设置变化。Wails 运行时能否修改标题栏主题，还待查。
- **托盘右键菜单**：在 Wails v3 beta 上可能弹不出来（#6161），目前用左键打开窗口代替。
- **`-race`**：本机没有 gcc，无法运行数据竞争检测。打算在 M9 完善 CI 时，在 GitHub 的 Windows runner（自带 MinGW）上加跑。
- **.rdp 属性重复时取哪一个**：目前取最后一个，这是推测，没有对照 mstsc 实测。只影响手工编辑过的文件。
- **RD 网关**：M4 已定为「可能走只警告、一定走才拦截」。mstsc 用 `/v:` 启动时是否采用 Default.rdp 里的网关设置，没有查到官方说法（显示设置确定会采用），M5 实测。
- **真实 mstsc 的行为**：
  - 已确认（2026-10-03）：对已连接的会话发 WM_CLOSE 会弹「远程会话即将断开连接」确认框；聚焦有效。
  - 原先以为 Win10 起凭据框由另一个进程承载、WM_CLOSE 关不掉；实测关得掉，但 mstsc 随后卡住（已改为不关凭据框，见「实连反馈与修复」）。
  - mstsc 会话窗口的类名 `TscShellContainerClass` 没有官方文档，是多年来的事实。将来如果变了，「断开」会退化成直接结束 mstsc（远程会话照样保留），不会卡住。
