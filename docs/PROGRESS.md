## M1 完成情况

全部是纯逻辑，不调用系统接口（`probe.Check` 和 `testutil` 只用标准库网络）。

- **`model`**
  - `Proxy`、`Profile`、`Target`、`Display`，以及 `Normalize` / `Validate`。
  - 校验返回 `FieldErrors`：一次列出全部问题，每条是「字段路径 + 代码」，界面据此逐项标红并翻译。
  - `ParseTarget` 解析 `host`、`host:port`、`[IPv6]:port`、裸 IPv6，`.rdp` 导入和粘贴地址共用。
  - `NewID` 生成 16 位小写十六进制 ID，兼作文件名。
  - 内置「直连」代理，ID 固定为 `direct`，不落盘。
- **`loopback`**：由 ID 经 SHA-256 派生 `127.(1-254).(1-254).(1-254)`；冲突时顺延到下一个空闲地址，搜索覆盖全范围一次，必然终止。
- **`rdpfile`**
  - 只读解析 .rdp，支持 UTF-16（LE/BE）和 UTF-8，有无 BOM 都行；非法字节替换成 U+FFFD，不会整份失败。
  - 能取出目标、用户名（含 `domain` 拼接）、显示设置、`/admin`，`Draft` 直接生成导入用的 Profile 草稿。
  - `Gateway().Verdict()` 判断 RD 网关：不会走 / 可能走 / 一定走。组策略的判断留给 M4。
- **`mstsc`**：`Args` 纯函数组装 `/v /f /multimon /span /w /h /admin`。
- **`probe`**
  - X.224 Connection Request / Confirm 的编码和解码。覆盖 6 种失败码、各种截断、非 RDP 应答，报错时附上收到的前几个字节。
  - `Check`：经线路发送 CR、读取 CC，可用 context 取消，不设超时。
- **`session`**
  - 纯函数 reducer：一次只跑一个步骤，每个步骤以一个事件结束。
  - 停止请求先记下，等在途步骤结束后统一清理；route check 会被主动取消。
  - 上游状态只在翻转时记日志。
- **`testutil`**：假 RDP 服务端，有 7 种应答方式，确认后回显数据，供 M2 隧道测试使用。

## M2 完成情况

还没有接入界面（M4 接入），所以目前只能靠测试验证。测试从不启动真实的 mstsc。

- **`route`**：`Dialer`、`Provider` 接口和直连实现。其他代理类型在 M3 接入，目前返回 `ErrUnsupported`。
- **`tunnel`**
  - 每个连接各自拨上游，双向拷贝，带字节计数。
  - 收到第一个上游字节时报告「已应答」；拨号失败或应答前被关闭时报告「失败」；mstsc 或隧道自己关闭的连接不报失败。
  - `Close` 会取消在途拨号，并等所有 goroutine 退出。
- **`session` actor**
  - 执行 reducer 给出的 effect，结果作为事件放回邮箱。邮箱是无界队列，投递永不阻塞，所以关闭隧道时不会和隧道的报告互相等待。
  - 先执行 effect 再发布状态，因此对外发布的「已结束」一定已清理完毕。
- **`session.Manager`**
  - 每个 profile 最多一个会话；重复连接时聚焦已有窗口；上一个会话还在结束中时，返回 `ErrEnding`。
  - `Quit` 强制结束全部会话，并等它们清理完再返回。
  - 回调串行、按顺序送达：旧会话的最后一条一定先于新会话的第一条。
  - 「直连到本机回环地址」在 preflight 阶段拒绝。
- **`mstsc` 启动器**（Windows）
  - 只用 `System32\mstsc.exe`。
  - 自己持有进程句柄，防止 PID 被复用：关闭、聚焦、结束都只会作用于自己启动的那个进程；进程退出后这些操作什么也不做。
- **`winx`**：按 PID 找可见、无 owner 的顶层窗口，用于 WM_CLOSE 和聚焦。
- **`testutil` 替身进程**：测试二进制以 helper 身份重新运行自己，扮演 mstsc。
  - 一种是屏幕外 1×1 的工具窗口，不激活、没有任务栏按钮，用来验证 WM_CLOSE 能让它退出。
  - 另一种没有窗口，一直运行到被结束，用来验证 Kill。

## M3 完成情况

同样尚未接入界面（M4 接入）。

- **引入 Xray-core v1.260327.0**
  - 它要求 Go ≥ 1.26，`go get` 因此把 `go.mod` 的 `go` 指令从 1.25.0 改成了 1.26。这是对工具链的最低要求，不是应用版本号。
  - exe 体积约增加 23 MB（正式构建参数，不含前端资源：9.9 MB → 32.8 MB）。按 M0 的 11 MB 估算，接入后约 34 MB；M4 接入后实测。
- **`engine`**
  - 每个进程只有一个 Xray 实例，没有 inbound；默认出站是 blackhole，没有带 tag 的连接一律丢弃。
  - outbound 按「代理 ID + 配置摘要」做引用计数：同一代理的多个会话共用一个；修改代理后，新会话用新的 outbound，旧会话继续用旧的直到结束；最后一个使用者释放时，outbound 被移除并关闭。
  - 每个连接用强制 tag 直接交给对应 outbound，不经过 Xray 的路由。
  - 每个连接都挂一个错误 tracker：出站失败时，Xray 给出的原因经由 `Read` 带回给隧道和线路检查。实测能拿到「SOCKS 账号被拒」「HTTP 407」「代理端口拒绝连接」这样的具体原因。
  - 拨号前先校验地址，因为非法地址会让 Xray panic。
  - `connIdle` 调到最大，属于已登记例外。
  - 日志桥接：错误和警告总是转发；info / debug 只在详细模式下转发；每条连接的访问日志不转发，因为里面有目标地址。
  - 直连不经过 Xray。
  - V2Ray 系协议虽然已经被链接进来，但在 M6 写好测试之前一律拒绝（`ErrUnsupported`）。
- **`probe.Latency`**：经线路发一次 HTTP GET，从连接一直算到响应头；任何 HTTP 状态都算通，不跟随重定向，可取消，不设超时。
- **`testutil/xraytest`**
  - 在测试进程里跑真实的 Xray SOCKS / HTTP 代理，可带账号。
  - 单独成包，这样只有需要 Xray 的测试才会链接它。
  - 端口用 `FreePort` 获取（已登记例外），因为 Xray inbound 没法监听 port 0 后再报告实际端口。
- **端到端测试**
  - 隧道 → 引擎 → SOCKS → 假 RDP：数据双向回显。
  - 完整会话（Manager + 引擎 + SOCKS 认证）：先做线路检查，会话结束后 outbound 被释放。
- **`route.DirectOnly` 已删除**：它是 M2 时的过渡实现，现在 engine 统一处理包括直连在内的所有类型。

## M4 完成情况

服务已经接入 app，界面还是 M0 的样子（M5 才做连接、代理页面）。用浏览器预览直接调用服务验证过，见「验证记录」。

- **`errcode`（新包）**
  - 各包的哨兵错误都带上稳定代码，如 `probe.notRdp`、`proxy.auth`、`session.loopbackDirect`。
  - 一棵错误树里取最有用的代码：强代码 > 系统错误（Winsock 错误码，如 `net.refused`）> 弱代码（`probe.noAnswer` 这类通用包装）> `unknown`。
  - Xray 的失败原因只存在于消息文本里（它的重试会把原始错误格式化成文字），所以由 engine 按文本归类：`proxy.auth`（SOCKS 账号被拒、HTTP 407）、`proxy.unreachable`（连不上代理）、`proxy.targetFailed`（代理明确回复连不上目标）、`proxy.dropped`（代理先应答再断开，v2rayN 这类 Xray 服务端到不了目标时就是这样）。都有真实代理的测试。
  - 会话状态和日志行带上 `code`，界面按代码翻译。
- **`secret`（新包）**
  - DPAPI（当前用户）加密代理的 `secret` 和 `outbound`，文件里存 `dpapi:<base64>`。
  - 凭据管理器：只写 GENERIC 类型，目标名 `TERMSRV/<回环地址>`，不带端口（依据见决策记录）。记住的密码用「本机」持久化；一次性密码用「本次登录」持久化，会话结束时删除，崩溃了也会在注销时消失。
  - 能读到并删除 mstsc 自己「记住我」存的域类型凭据，但从不写它。
- **`store`**
  - `proxies\<id>.json`、`profiles\<id>.json`：文件名就是 ID；先填默认值再解码；格式号更新的文件原样保留并跳过；损坏的改名为 `.corrupt`；打不开的（被占用、没权限）原样跳过；解不开的密码（来自别的用户或电脑）清空后照常载入。载入从不整体失败，每个问题都变成一条通知。
  - 新建连接时分配回环地址，全体连接查重；载入时发现地址缺失或冲突，ID 小的保留，其余重新分配并立即保存。
  - 拒绝存 ID `direct`、拒绝把代理设成 direct 类型；被连接使用的代理不能删（返回使用者名单），绝不悄悄改成直连。
- **`mstsc`（续）**
  - `Servers`：写 `UsernameHint`；删除某地址的全部记忆（含证书信任），连同「地址:任意端口」的键，所以改过本地端口后留下的旧键也会清掉。mstsc 用不用端口作键名没查到定论，先两种都写，M5 实测后收敛。
  - `CheckGateway`：读「文档」里的 `Default.rdp`（按已知文件夹定位）和 HKCU 的 RD 网关组策略。`gatewayusagemethod=1`（总是走网关）拦截；可能走网关（值 2、3，或策略启用且强制、或文件交给管理员默认值）只在会话日志里警告。
- **`logging`（新包）**
  - 日志文件 `%LOCALAPPDATA%\RDP-over-proxy\logs\app.log`，每个最多 2 MiB，另留 2 个旧文件。
  - 写入文件前脱敏：用户目录换成 `%USERPROFILE%`（路径里有 Windows 账户名）；已知的目标主机、代理服务器、RD 网关、用户名、连接名、分组名、代理名、代理密码换成 `<redacted>`；非回环 IP 换成 `<ip>`。已知名字只增不减，因为运行中的会话可能还在用已经改掉的主机名。内存里的环形缓冲不脱敏，供界面显示。
  - 连续相同的行只写一次，换了内容时补一句「上一行又重复了 N 次」（按状态翻转去重）。
  - Wails 运行时只收它的警告和错误：它的 debug、info 记录在任何日志级别下都不收，其中有的带着服务调用的参数，也就是密码（代码审查发现）；服务方法返回的预期错误也不收，它们会通过调用结果送到界面；其余记录里的 `args`、`result` 等载荷属性一律写成 `<omitted>`。
- **服务与事件（`api`）**
  - `ProfileService`：列表（含密码状态）、新建、修改、删除、忘记密码。改目标地址删除已存密码；取消「记住密码」只删本程序存的；改用户名时把本程序存的密码挪到新用户名下；删除连接一并清掉密码和 mstsc 对该地址的记忆；连接中的不能删（和「连接」互斥，不会删掉一个正在启动的连接）。
  - 所有凭据操作都经过一把锁，「先查再改」的组合操作在锁内完成；一次性密码不会覆盖本程序记住的密码（会话期间用户改为记住并存了新密码时，以新密码为准）。
  - `ProxyService`：列表（不含密码和 Xray 出站 JSON，两者都含凭据）、读取（含出站 JSON，供编辑）、新建、修改（可保留原密码）、删除、测速（`Latency`，可从前端取消）。
  - `SessionService`：连接（可带密码：「记住密码」的连接把它存为记住的密码，否则只用于本次会话）、断开（可强制）、聚焦、状态列表、会话日志、单独的线路检查（`CheckRoute`，可取消）。
  - `AppService`：通知列表与关闭、应用日志。
  - 事件：`data:changed`（全部连接和代理）、`sessions:changed`、`session:log`、`app:notice`。会话结束时也会发 `data:changed`，因为 mstsc 可能刚记住了密码。
  - 服务返回的错误统一成 `{code, message, fields, args}`，前端在被拒绝的调用的 `cause` 里拿到。
- **接入 app**
  - 启动顺序：先只读地看一眼设置（界面语言、日志级别），再创建 Wails 应用完成单实例判断（第二个实例在这里就退出），然后才正式载入设置（损坏时改名）、打开日志文件、载入数据、启动引擎、清理上次崩溃留下的一次性密码、注册服务。
  - 退出顺序：结束全部会话 → 关闭引擎 → 关闭日志。
  - 有会话在运行时，关闭窗口一律缩到托盘。
  - 设置里改日志级别立即生效，Xray 的 info/debug 只在 debug 级别转发。
  - 设置了 `RDP_OVER_PROXY_HOME` 时，单实例 ID 也按数据目录区分，开发和自测的运行不会与用户正在用的实例互相干扰。
- **前端**：重新生成绑定；`backend.ts` 导出全部服务、类型、事件名和 `errorOf`；两份语言文件加上 `errors`、`notices`、`log` 三组文案。Go 侧有测试检查每个错误码、通知代码和会话日志键在两份语言文件里都有翻译。
- **开发配置**：新增 `.claude/launch.json` 的 `preview` 配置，用 `data\preview` 作数据目录启动浏览器预览。

## 已知问题

- **还需实测的 mstsc 行为**（M5，见「下一步」第 5 条）：凭据目标名不带端口、`UsernameHint` 的键名。
- **mstsc 自己的「记住我」在 Win11 上可能无效**：它存的是域类型凭据，Credential Guard 开启时不能委派，每次还会再问密码。本程序存的 GENERIC 凭据不受影响。
- **浏览器预览被直接结束进程时不会走退出流程**（日志里没有 stopped）。这是预览工具的结束方式，桌面版正常退出已验证。
- **应用图标**：仍是 Wails 默认图标，M8 时换。
- **前端体积**：bundle 约 656 KB，是 Fluent UI 全量引入造成的，暂不处理。
- **exe 体积**：35.6 MB（M4 实测）。`infra/conf` 会把 Xray 几乎所有协议和传输都链接进来，精选 import 也省不了多少。
- **Xray 的日志处理器是进程级全局的**：每创建一个 Xray 实例都会把它替换掉。应用里只有一个实例，没有问题；但测试要检查引擎日志时，必须先启动 `xraytest` 代理，再启动引擎。
- **代理端口不通时，要等 Xray 内部重试约 1.5 秒才会报错**：这是 Xray 自己的行为，不是本程序的超时。
- **标题栏颜色**：只跟随系统主题，不随应用内的主题设置变化。Wails 运行时能否修改标题栏主题，还待查。
- **托盘右键菜单**：在 Wails v3 beta 上可能弹不出来（#6161），目前用左键打开窗口代替。
- **`-race`**：本机没有 gcc，无法运行数据竞争检测。打算在 M9 完善 CI 时，在 GitHub 的 Windows runner（自带 MinGW）上加跑。
